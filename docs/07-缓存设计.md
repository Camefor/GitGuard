# 缓存设计

> **范围说明**：GitGuard 是本地单进程 CLI 工具，**不涉及分布式缓存、CDN、浏览器缓存**。本文件只约定进程内内存缓存与少量落盘缓存的策略。

## 1. 缓存目标

| 目标 | 衡量 |
| --- | --- |
| 降低冷启动时间 | 启动期不做 I/O 密集的「规则加载 / 配置解析」反复操作；首次解析后缓存至进程结束 |
| 降低正则匹配热路径的开销 | 内置规则正则在进程启动时编译后缓存；每条扫描命令复用 |
| 降低重复 Git CLI 调用 | 一次 `scan` 中对同一仓库的元数据（HEAD、hooks 路径、`core.hooksPath`）只查一次 |

**反目标**：MVP 阶段不缓存扫描结果（无跨进程缓存需求）；不缓存差异文本（每次都从 Git 读取，保证 DR-04 一致性）。

## 2. 分层策略

| 层级 | 介质 | 典型 TTL | 命中优先级 | 数据类型 |
| --- | --- | --- | --- | --- |
| L0 进程内内存 | `ConcurrentDictionary` / `Lazy<T>` | 进程生命周期 | 1 | 编译后的 `Regex`、`DetectionRule` 列表、解析后的 `.gitguard.yml` |
| L1 本地文件 | `~/.local/share/gitguard/cache/` | 跨进程持久，手动失效 | 2 | 规则库版本摘要、字节级 fingerprint salt |

> MVP 阶段默认只启用 L0；L1 仅用于保存 `fingerprint_salt`（首次运行生成，之后保持稳定，避免跨 run 指纹漂移）。

## 3. 键命名规范

- L0 不需要显式 key（直接是字段 / 单例）。
- L1 文件命名：
  - `~/.local/share/gitguard/cache/fingerprint.salt`（32 字节随机数据）
  - `~/.local/share/gitguard/cache/rules.compiled.v1.bin`（可选：编译后规则二进制序列化缓存，预留，MVP 不启用）

## 4. TTL 与失效

| 数据域 | TTL 策略 | 失效触发 | 容忍过期场景 |
| --- | --- | --- | --- |
| 编译后 `Regex` | 进程生命周期 | - | - |
| `.gitguard.yml` 解析结果 | 进程生命周期 | 配置更改需重启进程（CLI 是短生命周期，无感知成本） | - |
| `fingerprint_salt` | 永久 | 文件被用户删除；文件损坏时重新生成（会导致历史指纹无法匹配） | 用户显式重置 |
| Git 元数据（HEAD、hooks 路径） | 单次 scan 内 | 进程退出 | - |

## 5. 并发回源与击穿防护

- MVP 为单线程扫描热路径，无「并发回源」问题。
- 后续桌面端（P3）启动多个仓库扫描时，`DetectionRule` 列表应为**不可变**单例（Immutable），线程安全。
- `fingerprint_salt` 的生成走 `AtomicWrite`（写临时文件 + rename），避免多进程启动时冲突。

## 6. 一致性策略

- 对于短生命周期 CLI 调用，内存缓存与底层数据天然一致（本次进程内不会被改）。
- `fingerprint_salt` 一旦生成不再变化；若用户手动删除，会导致**历史指纹无法命中新白名单**，用户需要重新登记。此行为必须在 `gitguard --help` 和 README 中说明。

## 7. 监控与告警

- MVP 不做缓存命中率监控。
- `--verbose` 日志中可输出每个检测器的「规则条数、总匹配次数」，用于用户自诊断性能问题。

## 8. 容量与成本

- L0 内存缓存：编译后规则 + 配置 ≤ 2 MB；对 Native AOT 单文件无影响。
- L1 文件缓存：仅 `fingerprint_salt`（32 字节）；可忽略。

## 9. 失败降级

- L0 失败：实际上是程序 Bug，直接 FailClosed（退出码 11）。
- L1 `fingerprint_salt` 读取失败：
  - 文件不存在 → 生成新 salt 并写入；写入失败视为非致命，使用内存 salt 继续（但警告「本次指纹不稳定」）。
  - 文件损坏 → 同上。
