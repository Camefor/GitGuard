# 权限设计

> **范围说明**：GitGuard 为本地单用户工具，**不涉及远程认证、RBAC、OAuth、JWT 等多用户系统的权限模型**。本文件聚焦在：本地文件权限、Hook 执行权限、密钥（指纹盐）管理、输入输出边界的脱敏约定，以及对应的审计留痕。

## 1. 角色与能力矩阵

| 角色 \ 能力 | 读写 `.gitguard.yml` | 读写用户配置 | 读写审计 DB | 安装/卸载 Hook | 调整严重度策略 |
| --- | --- | --- | --- | --- | --- |
| 当前 OS 用户（Developer） | ✓ | ✓ | ✓ | ✓ | ✓（受硬下限约束，见 §3） |
| 其他 OS 用户 | ✗（文件权限隔离） | ✗ | ✗ | ✗ | ✗ |
| root/Administrator | 读 ✓；写需显式确认 | 同左 | 同左 | 同左 | 同左 |

> 不设「GitGuard 自身用户」角色；工具运行在调用它的用户上下文。root 无特殊权限，但受操作系统本身所限不受普通文件 ACL 约束。

## 2. 认证机制

- 本地 CLI 不做认证。进程继承 OS 用户身份。
- 若未来桌面端或 CI 接入需要身份识别，走独立 ADR 评估。

## 3. 授权模型

**硬下限约束**（防止用户配置意外「关掉所有保护」）：

- `Severity = Critical` 的内置规则**不允许**在策略配置中被降级为 `Allow`。
- `scan.fail_closed` 默认 `true`；若用户显式设为 `false`，启动期打印警告并记录到审计。
- 不允许通过配置文件删除内置规则；只能禁用（`enabled: false`），且会记录到审计。

> 这些约束通过 `PolicyValidator` 在加载 `.gitguard.yml` 时强制执行；违反时 FailClosed 退出码 13。

## 4. 密钥与凭据管理

GitGuard 自身只需要一个本地密钥：**指纹盐（fingerprint salt）**。

| 凭据 | 存储位置 | 轮换周期 | 泄漏响应 |
| --- | --- | --- | --- |
| `fingerprint_salt`（32 字节随机） | `~/.local/share/gitguard/cache/fingerprint.salt`（Windows `%LOCALAPPDATA%\GitGuard\cache\`） | 不轮换（轮换会使历史指纹失效，影响白名单） | 不影响安全（仅用于防白名单跨机器碰撞）；泄漏可忽略 |

> **严禁**：
>
> - 不得把 `fingerprint_salt` 写入日志、审计、报告、JSON 输出。
> - 不得把被扫描的敏感原文写入任何文件（DR-02）。
> - 不得在 `.gitguard.yml` 中出现真实秘密的「反例」原文；用占位值并在注释中标注。

## 5. 文件权限

### 5.1 Unix（macOS / Linux）

| 文件 / 目录 | 期望权限 | 创建时设置方式 |
| --- | --- | --- |
| `~/.local/share/gitguard/` | `0700` | `Directory.CreateDirectory` + `File.SetUnixFileMode` |
| `~/.local/share/gitguard/audit.db` | `0600` | 创建后立即 `chmod` |
| `~/.local/share/gitguard/cache/fingerprint.salt` | `0600` | 同上 |
| `~/.config/gitguard/config.yml` | `0600` | 同上（如存在） |
| 仓库内 `.gitguard.yml` | 跟随仓库默认（不做强制） | - |
| 仓库内 `.git/hooks/pre-commit` | `0755`（可执行） | 安装时 `chmod` |

**启动期检查**：若 `audit.db` 或 `fingerprint.salt` 的 mode 不是 `0600`，启动期自动 `chmod` 并写入审计（事件 `FilePermissionFixed`）。

### 5.2 Windows

- 相关目录放在 `%LOCALAPPDATA%\GitGuard\`，继承用户目录 ACL。
- 启动期检测 `audit.db` 是否允许 `Everyone` / `Authenticated Users` 读写；若是则重置 ACL 为仅 `CurrentUser`。

## 6. Hook 执行权限

- `pre-commit` / `pre-push` / `post-commit` 脚本由 Git 以当前 OS 用户执行，无需额外提权。
- Hook 分发器脚本：
  - Unix：`#!/bin/sh` + `exec` 调用 GitGuard 可执行文件（绝对路径或 PATH 查找）。
  - Windows：Git for Windows 下 `#!/bin/sh` 仍有效（走 MSYS2 bash）；兼容。
- 分发器只做「调用 GitGuard + 调用备份的原 Hook」；不执行任何用户输入命令。
- GitGuard 可执行文件路径由 `install` 时固化到分发器脚本中；避免 PATH 歧义导致误用其他二进制。

## 7. 审计日志

> 对所有安全相关事件进行脱敏审计，详细 schema 见 `05-数据库设计.md` §4.5 `audit_logs`。

| 事件 | 触发 | 必记字段 | 保留期 |
| --- | --- | --- | --- |
| `ScanCompleted` | 每次扫描结束 | run_id, repo_path, scan_type, result, exit_code, duration_ms | 180 天 |
| `BypassDetected` | 侦测到 `--no-verify` 或 `GITGUARD_SKIP=1` | run_id, commit_sha, detected_at | 180 天 |
| `HookInstalled` / `HookUninstalled` | 安装/卸载 Hook | repo_path, hook_type, version, had_legacy_hook | 永久 |
| `AllowlistChanged` | Add / Remove 白名单 | entry_id, action, rule_id?, path_pattern?, fingerprint?, reason | 永久 |
| `PolicyOverride` | 用户降级了某个默认 block 规则 | rule_id, from, to | 永久 |
| `FilePermissionFixed` | 启动期修复了异常权限 | file_path, prev_mode, new_mode | 180 天 |
| `FailClosed` | 任何 FailClosed 退出 | exit_code, error_code, message_hash | 180 天 |

**不可记录字段**：敏感原文、Token、密码、完整敏感行、`fingerprint_salt` 本身。

## 8. 数据分级与访问控制

| 等级 | 示例数据 | 存储 | 访问控制 |
| --- | --- | --- | --- |
| 公开 | 规则 ID、规则名称、GitGuard 版本 | 任意位置 | 任意 |
| 内部 | 文件路径、行号、脱敏片段（最多 32 字符）、指纹（SHA-256） | SQLite / 日志（已脱敏） | 当前 OS 用户 |
| 机密 | 原始敏感文本、`fingerprint_salt` | **禁止持久化** | 不存在于持久层 |

> 「机密」等级数据只存在于**内存**，用完立即释放（引用置空）。可用 `.NET` 的 `CryptographicOperations.ZeroMemory`（P2 严格实现）。

## 9. 常见攻击面与防护

| 攻击面 | 风险 | 防护 |
| --- | --- | --- |
| 恶意 `.gitguard.yml` 关闭所有规则 | 伪装合规但完全失防 | §3 硬下限；关键规则不可降级为 `Allow` |
| 攻击者替换 GitGuard 可执行文件为空操作 | Hook 调用空壳，默认放行 | 本地单机场景下与系统其他可执行文件风险等级一致；`gitguard status` 显示版本摘要以便用户校验 |
| 恶意正则（ReDoS） | 用户自定义规则导致 Regex 回溯爆炸 | `Regex.MatchTimeout = 200ms`，超时 FailClosed 并禁用该规则直到用户修复 |
| 符号链接攻击把审计 DB 指向他处 | 覆盖目标文件 | 启动期 `realpath` 校验 `audit.db` 不是 symlink；是 symlink 则拒绝启动 |
| 恶意 Git 仓库通过超长行 / 二进制触发资源耗尽 | OOM | 单文件最大字节数 1 MiB（`scan.max_file_bytes`）；二进制通过 heuristic 检测跳过 |
| 日志注入（恶意文件路径含控制字符） | 终端 escape 伪装输出 | 输出前用 `TerminalSanitizer` 过滤 ANSI 控制字符 |
