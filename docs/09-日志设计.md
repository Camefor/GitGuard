# 日志设计

## 1. 日志目标

GitGuard 的日志承担四类职责：

1. **开发者排错**：Hook 失败时能通过 `--verbose` 看到完整上下文。
2. **安全审计**：所有阻断、绕过、白名单变更、权限修复事件进入 SQLite（见 `08-权限设计.md` §7）。
3. **性能自诊断**：每次扫描输出规则级耗时摘要，用户自判断是否禁用高耗规则。
4. **行为可追溯**：出现误报时能通过 `run_id` + `audit_logs` 复盘。

GitGuard **不做**：无云端日志上报、无聚合告警平台、无告警短信/邮件。所有告警动作都是「终端输出 + 本地 SQLite 记录」。

## 2. 日志分级

| 级别 | 用途 | 必打字段 | 禁止事项 |
| --- | --- | --- | --- |
| Trace | 规则级逐行匹配（仅 `--verbose --trace`） | `rule_id, file_path, line, duration_us` | 包含敏感原文 |
| Debug | 关键决策、Git 命令调用、配置路径、规则耗时摘要（`Scan.RuleTiming`） | `category, decision, context`；规则耗时含 `rule_id, duration_us` | 原始敏感文本 |
| Information | 扫描开始/结束、安装/卸载 Hook、白名单变更 | `event_type, run_id, repo_path(hash), result` | 完整敏感行 |
| Warning | 可能的误报配置、规则正则超时、文件被跳过 | `rule_id, reason` | 敏感原文 |
| Error | FailClosed 导致阻断 | `error_code, exit_code, trace_id` | 敏感原文、stack trace 中的敏感参数 |
| Critical | 启动期致命错误（权限损坏、DB 文件无法打开） | `error_code, hint` | 同上 |

默认级别 `Information`；`--verbose` 升到 `Debug`；`--verbose --trace` 升到 `Trace`。

`--verbose` 在扫描完成后按 `rule_id` 字典序输出 `Scan.RuleTiming`：每条实际执行过正则求值的规则一行，含求值次数 / 命中次数 / 累计 `duration_us`（仅在文件 glob、行跳过、上下文关键字门控通过后才计时）；普通扫描不创建计时器。

## 3. 结构化字段

- **约定**：`snake_case`。
- **输出格式**：
  - 终端（stderr）：人类可读单行，带可选颜色（`--no-color` 禁用）。
  - 文件（可选 `--log-file <path>`）：每行一条 JSON。
  - SQLite 审计表：按事件类型反规范化到 `audit_logs.payload_json`。

| 字段 | 类型 | 必带场景 | 示例 |
| --- | --- | --- | --- |
| `timestamp` | ISO8601 UTC | 所有日志 | `2026-10-15T06:30:12.345Z` |
| `level` | string | 所有 | `information` |
| `category` | string | 所有 | `Scan.Staged`、`Scan.RuleTiming`、`Hook.Install`、`Allowlist` |
| `message` | string | 所有 | 已脱敏文本 |
| `run_id` | string | 扫描相关 | UUIDv7 |
| `repo_path_hash` | string(16) | 多数 | SHA-256 截断（避免原始路径暴露） |
| `rule_id` | string | 规则命中/警告 | `GGD/SECRET/AWS-AKID` |
| `exit_code` | int | 结束日志 | 1 |
| `duration_ms` | int | 结束日志 | 183 |
| `duration_us` | int | 规则耗时摘要（`Scan.RuleTiming`，`GGD-0020`） | 345 |
| `error_code` | string | Error / Critical | `GIT_COMMAND_FAILED` |
| `trace_id` | string | Error / Critical | 短 ID 便于反馈时用户引用 |

> **严禁字段**：`snippet_raw`、`token`、`password`、`fingerprint_salt`、`stacktrace_with_args`。

## 4. 分布式追踪

本地单进程无需分布式追踪。保留 `ActivitySource` 命名空间 `GitGuard` 以便性能基准与 `--trace` 打点。

## 5. 指标（本地）

MVP 不接外部监控系统，仅在扫描结束时输出一条结构化 Summary：

```json
{
  "event_type": "ScanSummary",
  "run_id": "0192...",
  "duration_ms": 183,
  "files_scanned": 42,
  "rules_evaluated": 36,
  "blocked": 0,
  "warned": 2,
  "ignored_by_allowlist": 1,
  "fail_closed_triggered": false,
  "detector_breakdown": {
    "secret": { "hits": 0, "duration_ms": 42 },
    "privacy": { "hits": 1, "duration_ms": 30 },
    "local_path": { "hits": 1, "duration_ms": 50 },
    "url": { "hits": 0, "duration_ms": 25 }
  }
}
```

该 Summary 同时写入 `audit_logs(category='Scan', event_type='ScanCompleted')`。

> `GGD-0020` 已落地的规则级耗时以 `Scan.RuleTiming` Debug 日志逐规则输出（`rule_id` / 求值次数 / 命中次数 / `duration_us`），不写入审计库；上例中的 `detector_breakdown` 为规划形态。

## 6. 告警规则

**无外部告警**。用户感知异常的唯一通道是：

- CLI 退出码（Hook 调用 Git 的交互中直接呈现）。
- stderr 终端输出。
- 本地审计可查询（`gitguard audit list --result Blocked`，`GGD-0022`；导出入 `gitguard audit export`）。

Hook 自身不发邮件/消息，避免把工具变成通知平台。

## 7. 日志采集与聚合

- 默认不写日志文件；避免磁盘占用。
- 用户可通过 `--log-file <path>` 启用文件日志；或配置 `.gitguard.yml`：

  ```yaml
  logging:
    file:
      enabled: false
      path: "~/.local/share/gitguard/logs/gitguard.log"
      max_bytes: 10485760  # 10 MiB
      max_files: 5
  ```

- SQLite 审计表总是启用。
- 不集成 ELK / Loki / Grafana / Sentry 等平台（DR-01）。

## 8. 保留与成本

| 日志类型 | 保留期 | 存储介质 | 预估成本 |
| --- | --- | --- | --- |
| 终端 stderr | 一次性 | - | 0 |
| 文件日志（可选） | 滚动 5 份 × 10 MiB = 50 MiB 封顶 | 本地磁盘 | 可忽略 |
| 审计表 `audit_logs` | 180 天默认 | SQLite | 假设每天 100 次扫描 × 1 KB payload ≈ 18 MB 稳态 |

## 9. 安全与隐私

> 本节是 DR-02「零明文留存」的具体落地。

### 9.1 禁止入日志的字段

- 敏感原文（Token、密码、密钥、身份证、手机号完整值）。
- 完整敏感行文本（即便已部分遮蔽，长度不得超过 32 字符）。
- `fingerprint_salt`。
- Git 远程 URL 的凭据部分（`https://user:pass@host`）。
- OS 环境变量中以 `TOKEN / KEY / SECRET / PASSWORD` 结尾的变量名的 **值**（名本身可以记）。

### 9.2 强制脱敏流水线

所有日志输出必须经过 `SanitizingLogger`：

1. **Masker**：对任何已识别为敏感的字段应用「保留前后 2 字符 + 中间 `*`」。
2. **TerminalSanitizer**：去除 ANSI 控制字符、ASCII `0x00~0x1F`（允许 `\n` `\t`）。
3. **PathAnonymizer**：对 `repo_path` 在非 `Debug` 级日志中替换为 `repo_path_hash`。

### 9.3 验证

- 单测 `TC-DR-02-01`：注入「金丝雀 Token」`AKIA_SENTINEL_${run_id}`，运行扫描后在 audit.db、log 文件、JSON 输出中搜索该 Token 全文；命中即测试失败。
- CI 阶段使用 `grep` 对 build artifact 做二次验证。
