# 异常处理设计

## 1. 错误分类

GitGuard 严守 **FailClosed（DR-03）**。所有错误分类决定「用什么退出码阻断」而不是「是否阻断」。

| 类别 | 定义 | 典型示例 | 处理策略 | 对应退出码 |
| --- | --- | --- | --- | --- |
| 用户错误 | 参数、配置、仓库环境错误 | 未知命令 / 选项冲突、`.gitguard.yml` 版本缺失、非 Git 仓库 | 阻断 + 明确提示修复 | 2 / 7 / 13 / 20 |
| 业务阻断 | 命中阻断级规则 | 真实 API Key 泄漏 | 阻断 + 报告 | 1 |
| 依赖失败 | Git CLI 失败、Gitleaks 不可用 | git 命令超时、exit!=0 | **全部 FailClosed 阻断**；Gitleaks 不可用则降级（不属于异常） | 10 |
| 系统错误 | 代码缺陷、未处理分支、本地存储故障 | NullReferenceException、Regex 超时、OOM、审计库读写失败 | 阻断 + 收集 trace_id | 11 / 14 / 99 |

> **关键原则**：对于 `pre-commit` / `pre-push` 的 Hook 调用链，用户体验排名**低于**安全。宁可用户不方便，也不能让一次异常变成一次放行。

## 2. 异常传播边界

GitGuard 分层架构中的异常传播规则：

| 层 | 允许抛出 | 必须捕获 | 必须转换为 |
| --- | --- | --- | --- |
| `Core.Domain` | `InvariantViolationException`（DR 守卫） | 底层异常不进入此层 | - |
| `Detection` | 规则正则异常（`RegexMatchTimeoutException`） | - | `DetectionException`（带 rule_id） |
| `Application` | `UseCaseException` / `HookException` 系列 | 捕获 `DetectionException` / `GitException` 并封装 | `ScanResult(Failed, exit_code)` / Hook 安装报告 |
| `Infrastructure` | `GitException`、`SqliteException`、`IOException` | - | 保留原始异常，Application 层封装 |
| `Cli` | - | 捕获所有未处理异常 → `UnknownErrorExitCode(99)` | 用户友好信息 |

- **Core.Domain 不能依赖 `Microsoft.Data.Sqlite`**，更不能 catch `SqliteException`。
- **Infrastructure 不能抛纯粹的 `Exception`**；必须用项目定义的异常类型（`GitException` / `SqliteException` 包装）。
- `GitException` 定义在 `GitGuard.Core` 根命名空间：`Cli` 层需要 `catch` 它并映射退出码，而 `Cli` 不得引用 `Infrastructure`；错误码经 `ErrorCode` 属性携带（取自 §4 登记表），并附 `ExitCode` / `StandardError` 供诊断。
- `HookException` 同样定义在 `GitGuard.Core` 根命名空间（`GGD-0008`）：由 Application 层的 Hook 用例抛出，`Cli` 需 catch 并映射退出码（`WRITE_PERMISSION_DENIED` → 3，`UNKNOWN_HOOK_PRESENT` → 4，`INSTALL_IN_PROGRESS` → 50），而 `Cli` 不得引用 Application。

## 3. 全局异常处理

实现位于 `GitGuard.Cli.CliApplication.RunAsync`（`Program` 仅解析宿主环境后调用它）。三段式：

```csharp
// ① 解析期：未知命令 / 未知选项 / 选项取值非法 / 参数组合非法 → 退出码 7
ParseResult parseResult = root.Parse(args);
if (parseResult.Errors.Count > 0)
{
    writer.WriteUsageError(errors, traceId);
    return ExitCodes.USAGE_ERROR;   // 7：不触碰仓库与配置，不落任何审计
}

// ② 执行期：命令动作抛出的异常统一在出口映射
try
{
    return await parseResult.InvokeAsync(configuration, cancellationToken);
}
catch (Exception exception)
{
    int exitCode = ExitCodeMapper.Map(exception);
    writer.WriteError(exitCode, ExitCodeMapper.ErrorCodeOf(exception), message, traceId);
    if (exitCode == ExitCodes.UNKNOWN_ERROR)
    {
        CrashLogWriter.TryWrite(session, traceId, exception);   // 脱敏崩溃日志（不再抛出）
    }

    return exitCode;
}
```

`ExitCodeMapper.Map` 的分类规则（异常类型 → 退出码）：

| 异常 | 退出码 |
| --- | --- |
| `GitException`（`NOT_A_GIT_REPOSITORY`） | 2 |
| `GitException`（其余 ErrorCode） | 10 |
| `HookException`（`WRITE_PERMISSION_DENIED` / `UNKNOWN_HOOK_PRESENT` / `INSTALL_IN_PROGRESS`） | 3 / 4 / 50 |
| `HookException`（未登记 ErrorCode） | 99 |
| `ConfigurationException` | 13 |
| `BaselineException`（`BASELINE_INVALID`） | 13 |
| `BaselineException`（`BASELINE_WRITE_FAILED`） | 31 |
| `DetectionException` | 11 |
| `SqliteException` | 14 |
| `OperationCanceledException` | 12（取消在 CLI 上作为超时的变体） |
| 其他未分类异常 | 99 |

**禁止写法**：

- `catch (Exception) { return 0; }`（违反 FailClosed）
- `catch (Exception) { throw; }` 作为「包装」唯一动作（没有分类意义）
- 吞异常（空 catch 块）
- 让解析错误越过 ① 进入命令动作（会把用法错误误报为配置 / 仓库错误）

## 4. 错误响应契约

遵循 `06-API接口设计.md` §4.4 的错误 JSON Schema。错误码来自已登记的枚举：

| error_code | exit_code | 场景 |
| --- | --- | --- |
| `CLI_USAGE_ERROR` | 7 | 未知命令 / 未知选项 / 选项取值非法（`--format` 非 `text\|json`、`--hook` 非 `pre-commit\|pre-push`、`allowlist remove` 的 `--id` 非 GUID、`allowlist list` 的分页参数越界）/ 参数组合非法（`scan` 未指定或同给 `--staged` 与 `--push`、`--trace` 未与 `--verbose` 同用） |
| `NOT_A_GIT_REPOSITORY` | 2 | 当前目录不是 Git 仓库 |
| `WRITE_PERMISSION_DENIED` | 3 | Hook 相关文件读写失败（hooks 目录创建、备份复制、脚本写入、回读探测） |
| `UNKNOWN_HOOK_PRESENT` | 4 | 目标 Hook 存在但无法安全包裹：二进制（头部含 NUL）/ 符号链接 / 「遗留备份 + 非托管目标」；前两者可加 `--force` 显式接管，遗留备份冲突 `--force` 不适用 |
| `GIT_COMMAND_FAILED` | 10 | Git 子进程非零退出、超时或无法启动；git 输出无法解析（unified diff 的 hunk 头 / 文件头格式不符） |
| `DETECTOR_FAILED` | 11 | 任何 `IDetector` 抛异常 |
| `SCAN_TIMEOUT` | 12 | 整体扫描或单规则超时 |
| `CONFIG_INVALID` | 13 | `.gitguard.yml` / 用户级配置解析失败或违反硬下限（含未知 `version`、YAML 语法错误、取值越界、`use_gitleaks: true` 未实现开关） |
| `BASELINE_INVALID` | 13 | 基线文件读取 / 解析失败（文件损坏、schema 不符、条目不合法；`GGD-0032`） |
| `AUDIT_STORE_FAILED` | 14 | 审计库打开 / 迁移 / 读写失败（`SqliteException` 逃逸到 CLI 出口） |
| `ALLOWLIST_VALIDATION_FAILED` | 20 | 白名单 `add` 参数不合法（无条件 / reason 过短 / 指纹格式非法；`GGD-0030`） |
| `ALLOWLIST_NOT_FOUND` | 21 | 要删除的条目不存在（`GGD-0030`） |
| `AUDIT_RUN_NOT_FOUND` | 30 | 查询不存在的 run_id（`audit view` v0.2 预留） |
| `AUDIT_EXPORT_FAILED` | 31 | 审计导出 IO 失败（`audit export`，`GGD-0022`）；基线文件写入失败复用该退出码（`BASELINE_WRITE_FAILED`，`GGD-0032`） |
| `BASELINE_WRITE_FAILED` | 31 | 基线文件写入失败（路径不可写 / 为目录 / IO 错误；`GGD-0032`） |
| `RULE_NOT_FOUND` | 40 | 规则 ID 不存在 |
| `INSTALL_IN_PROGRESS` | 50 | 已有并发 install / uninstall 持锁（`<git-common-dir>/gitguard.install.lock`） |
| `UNKNOWN_ERROR` | 99 | 未分类异常 |

## 5. 降级策略

| 失败点 | 检测方式 | 降级分支 | 用户提示 |
| --- | --- | --- | --- |
| Gitleaks 可执行文件缺失 | 启动期 PATH 探测 | 禁用 `GitleaksAdapter`，继续用内置规则 | `Information` 级日志："Gitleaks 适配器已禁用" |
| `fingerprint.salt` 读取失败 / 损坏 / 落盘失败 | 文件 IO | 内存生成临时 salt（`IsTransient`），警告；本次运行的指纹不跨运行稳定 | `Warning`: "指纹盐临时生成，白名单可能需要重登记" |
| 配置文件含未知字段 / 暂未接线开关 | 宽松解析（`Policy.md` §9） | 记入 `warnings`，不阻断：未知键、`scan.fail_closed: false`、`scan.pre_commit` / `scan.pre_push: false`、`logging.verbose` | `Warning` 逐条列出（`--format json` 时在 `warnings[]`） |
| 崩溃日志写入失败 | `CrashLogWriter.TryWrite` 返回 `null` | 静默跳过：退出码仍为 99，错误报告已输出到 stderr | 无（不再抛出二次异常） |
| 单个 `IDetector` 异常 | catch | **不降级，直接 FailClosed**（exit_code 11） | 列出失败规则 ID，建议暂时 `enabled: false` 并提交 Issue |
| Regex 超时 | `RegexMatchTimeoutException` | **不降级，FailClosed**：抛 `DetectionException`（`DETECTOR_FAILED`，exit 11）终止本次扫描，不再继续其他规则 | 列出失败规则 ID，建议修复或移除该正则 |
| SQLite 写失败 | catch | 当前扫描结果照常返回，但审计日志写入失败将被记为 `AuditWriteFailed` 事件（下次启动尝试补写） | `Warning`: "审计写入失败" |
| 日志文件写满 | IO 异常 | 转到 stderr，不阻断业务 | `Warning` |
| unified diff 输出无法解析 | 解析层格式校验（hunk 头 / 文件头） | **不降级，FailClosed**：抛 `GitException`（`GIT_COMMAND_FAILED`，exit 10）；异常消息不回显差异内容（DR-02） | `Error`: "unified diff 输出无法解析；按 FailClosed 处理" |
| 配置文件违反硬下限（降级 critical 为 allow） | `PolicyValidator` | 启动失败 FailClosed | `Error`: 指出哪条规则违规 |

> **FailClosed 不是降级**：以上「不降级」项必须阻断。

## 6. 重试与熔断

| 场景 | 策略 |
| --- | --- |
| SQLite `BUSY` 错误 | 指数退避重试 3 次（50ms, 100ms, 200ms） |
| Git 子进程超时 | **不重试**，直接 FailClosed（避免对慢 Git 环境放大延迟） |
| Gitleaks 子进程异常 | 不重试；适配器直接报告 `DETECTOR_FAILED` |
| Regex 正则超时 | **不重试**；FailClosed 终止扫描并列出失败规则 ID |

MVP 不引入熔断器（本地短生命周期无必要）。

## 7. 前端错误呈现（CLI 终端）

- 终端输出遵循「醒目 + 简洁 + 可操作」；文本报告走 **stderr**（stdout 留给 `--format json` 的机器可读输出）：

  ```text
  ✖ GitGuard 失败（exit_code=13）
    错误码：CONFIG_INVALID
    原因：配置文件 YAML 语法错误：...（第 15 行）
    trace_id：XK3P-9A2L
  ```

  用法错误（退出码 7）单独成形，附 `--help` 指引：

  ```text
  ✖ 用法错误
    原因：scan 必须且只能指定 --staged 或 --push 之一。
    提示：运行 gitguard --help 查看用法。
    trace_id：XK3P-9A2L
  ```

- **禁止**：输出完整 stack trace（除非 `--verbose`）。
- **禁止**：在 message 中暴露密钥明文与 ANSI 控制字符（`MessageSanitizer` 统一净化所有写往终端与日志的文本）。
- **允许**：输出 `trace_id`，用户反馈 Issue 时引用。
- **彩色策略**：异常用红色、警告用黄色、成功用绿色；`--no-color` / `NO_COLOR` 环境变量 / 非 TTY（stderr 被重定向）时自动禁用。
- `--format json` 时仍为 `gitguard.error.v1`（stdout），日志继续走 stderr，互不污染。

## 8. 排查支持

- 每次扫描生成唯一 `run_id`（UUIDv7）；每次运行生成短 `trace_id`（`XXXX-XXXX`），两者均在错误输出中附带。
- `gitguard audit list` 可按分页 / 时间 / 结果筛选查询本地审计库，`gitguard audit export` 可导出脱敏 JSON / CSV（`GGD-0022`）；`gitguard audit view <run_id>` 的完整脱敏事件链查看为 v0.2。
- `--verbose` 把日志级别降到 `Debug`；`--verbose --trace` 到 `Trace`（Trace 必须与 `--verbose` 同用）；`logging.verbose: true` 等价于常带 `--verbose`。
- `--log-file <path>` 或 `logging.file` 可把 JSON-lines 日志落盘（按 `max_bytes` / `max_files` 滚动）；否则日志仅走 stderr。
- 崩溃信息（退出码 99）写入用户数据目录 `crash/` 子目录的 `<时间戳>-<trace_id>.log`（已脱敏）：Linux `~/.local/share/gitguard/crash/`（或 `$XDG_DATA_HOME/gitguard`）、macOS `~/Library/Application Support/GitGuard/crash/`、Windows `%LOCALAPPDATA%\GitGuard\crash\`；用户可随 Issue 一起提交。
