# 桌面组件设计（Avalonia，P3 阶段）

> **交付阶段**：同 `11-前端UI设计.md`，v0.3 启动桌面端时才落地。MVP 阶段仅保留骨架。

## 1. 组件分层

| 层级 | 职责 | 可依赖 | 典型组件 |
| --- | --- | --- | --- |
| 原子 | 无业务含义的最小单位 | 无 | `SeverityBadge`、`PillButton`、`CodeBlock` |
| 复合 | 组合原子解决具体 UI 模式 | 原子 | `FindingRow`、`AllowlistForm`、`HookStatusCard` |
| 业务 | 承载业务语义，绑定 ViewModel | 原子 + 复合 | `RepositoriesView`（`GGD-0042` 已落地）、`RepoDetailView`、`ScanHistoryView`（`GGD-0043` 已落地）、`AllowlistView`（`GGD-0044` 已落地）、`RulesView`（`GGD-0045` 已落地）、`LogsView` / `SettingsView`（`GGD-0046` 已落地） |
| 页面/路由 | 导航入口，编排用例 | 业务 + 布局 | `MainWindow`（导航壳）、`SettingsPage` |

> **实现说明（`GGD-0041` / `GGD-0042` / `GGD-0043` / `GGD-0044` / `GGD-0045` / `GGD-0046`）**：`GGD-0041` 落地骨架文件；`GGD-0042` 创建 `Views/RepositoriesView`、`Services/IRepositoryOperations` 与 `RepositoryOperations`，并补齐仓库页三个 ViewModel；`GGD-0043` 新增 `Views/ScanHistoryView`、扫描历史三个 ViewModel、`IEditorLauncher` / `ShellEditorLauncher`，并在 `IRepositoryOperations` 扩展分页历史与运行明细查询；`GGD-0044` 新增 `Views/AllowlistView`、白名单两个 ViewModel，并在 `IRepositoryOperations` 扩展全局白名单查询 / 新增 / 删除；`GGD-0045` 新增 `Views/RulesView`、规则三个 ViewModel、`IRuleOperations` / `RuleOperations`，并在 `MainViewModel` 接入规则页；`GGD-0046` 新增 `Views/LogsView` / `Views/SettingsView`、日志与设置共七个 ViewModel、`IAuditOperations` / `AuditOperations`、`DesktopSettings` / `ISettingsOperations` / `DesktopSettingsService`、`IExportPathPicker` / `StorageProviderExportPathPicker` 与 `DesktopServices` 聚合，并把 `AppState` 扩展为语言 / 主题 / 版本三态；`Controls` / `Resources` 仍为规划目录。界面文案由 `Localization/DesktopText.cs` 集中维护，取代原计划的 `Resources/zh-CN.axaml` / `en-US.axaml`——避免资源字典重载与反射，语言切换只刷新绑定属性。

**命名**：

- View（`*View.axaml`）：仅承担 UI 渲染；逻辑进 ViewModel。
- ViewModel：`CommunityToolkit.Mvvm` 风格的 `ObservableObject` + `RelayCommand`。
- Controls（原子/复合）：无 ViewModel，纯 Props；通过 `StyledProperty` 暴露。

## 3. 组件契约

### 3.1 `SeverityBadge`

- **Props**：

| 名称 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `Severity` | `Severity` | 是 | - | Critical/High/Medium/Low |
| `Compact` | `bool` | 否 | false | 紧凑模式 |

### 3.2 `FindingRow`

- **Props**：`Finding`（领域模型）
- **Events**：
  - `OpenInEditor`（载荷 `{ FilePath, LineNumber }`）：请求外部编辑器打开。
  - `AddToAllowlist`（载荷 `Fingerprint`）：触发白名单对话框。
- **Slots**：无

### 3.3 `AllowlistForm`

- **Props**：`AllowlistDraft`（可空，表示新建）
- **Events**：`Submit`（载荷 `AllowlistDraft`）、`Cancel`
- **校验**：三条件至少一个；Reason ≥ 5 字符；校验失败时阻止 `Submit` 事件外发。

### 3.4 `RepositoriesView`（GGD-0042）

- **数据源**：`RepositoriesViewModel`（构造注入 `IRepositoryOperations` 与初始语言）。
- **布局**：左栏 340px（登记路径输入、登记 / 刷新按钮、已登记仓库列表与空状态），右栏为仓库详情（名称 / 路径 / 目录缺失提示、GitGuard 与 Git 版本、Hooks 目录、Hook 状态行、最近扫描摘要、扫描 / 移除操作与二次确认条）。
- **服务契约**：`IRepositoryOperations` 暴露 `ListAsync` / `RegisterAsync` / `RemoveAsync` / `LoadDetailAsync` / `ScanAsync`，实现类 `RepositoryOperations` 负责创建 `GitGuardSession` 子会话并以 `Task.Run` 把 SQLite / Git 访问移出 UI 线程。ViewModel 测试以假对象驱动，不启动 Avalonia。
- **状态**：`IsBusy`（列表级操作）、`IsDetailLoading`、`IsScanning`、`IsRemoveConfirmationVisible`、`IsEmpty`、`IsSelectPromptVisible`、`CanInteract`；详情请求以递增版本号丢弃过期响应。
- **错误**：`RepositoryException` 按 `ErrorCode` 映射中 / 英提示；其他异常直接展示消息。消息分为列表级（`ListMessage`）与详情级（`DetailMessage`），不弹模态框。
- **本地化**：`Relocalize` 刷新页面标签、列表项缺失徽标、Hook 状态行与最近扫描摘要；缓存的仓库页在全局语言切换时同样刷新。

### 3.5 `ScanHistoryView`（GGD-0043）

- **数据源**：`ScanHistoryViewModel`（构造注入 `IRepositoryOperations`、`IEditorLauncher`、返回回调与初始语言），由 `RepositoriesViewModel.History` 持有并以覆盖层呈现。
- **布局**：三栏 300 / 330 / 自适应——扫描时间线（每页 20 条、上一页 / 下一页与页码）、发现项列表（规则 ID / 位置 / 严重度 / 提交短 SHA）、发现项详情（规则、严重度、提交、位置、脱敏片段、指纹与「在编辑器中打开」）。
- **服务契约**：`IRepositoryOperations` 新增 `QueryScanHistoryAsync` / `LoadScanRunAsync`；`IEditorLauncher.OpenAsync` 返回 `EditorLaunchStatus`（`Opened` / `RepositoryMissing` / `FileMissing` / `PathOutsideRepository` / `LaunchFailed`），实现类 `ShellEditorLauncher` 解析 `GITGUARD_EDITOR` → `VISUAL` → `EDITOR`，已知编辑器附带行号，否则回退系统文件关联。
- **状态**：`IsLoadingPage` / `IsLoadingRun`、`SelectedRun` / `SelectedFinding`、`IsEmpty` / `IsSelectRunPromptVisible` / `IsNoFindingsVisible` / `IsSelectFindingPromptVisible`、`CanGoPrevious` / `CanGoNext` / `CanOpenInEditor`；页面与运行请求各持递增版本号，快速切换时丢弃过期响应。
- **脱敏边界**：`FindingItemViewModel` 只暴露 `SnippetMasked` 与 `Fingerprint.Hex`，不持有原文；编辑器失败仅显示本地化原因，不展示进程原始输出。
- **本地化**：`Relocalize` 刷新页面标签、分页文案、运行项结果 / 扫描类型 / 计数与发现项严重度。

### 3.6 `AllowlistView`（GGD-0044）

- **数据源**：`AllowlistViewModel`（构造注入 `IRepositoryOperations`、返回回调与初始语言），由 `RepositoriesViewModel.Allowlist` 持有并以覆盖层呈现。
- **布局**：左栏为白名单条目列表（规则 ID / 路径 glob / 指纹预览 / 原因 / 登记人与时间 / 过期时间，每页 20 条与上一页 / 下一页），右栏为新增表单（规则 ID / 路径 glob / 指纹 / 原因）与删除二次确认条。
- **服务契约**：`IRepositoryOperations` 新增 `QueryAllowlistAsync` / `AddAllowlistAsync` / `RemoveAllowlistAsync`，直接复用 `AllowlistListUseCase` / `AllowlistAddUseCase` / `AllowlistRemoveUseCase`，`createdBy` 取 `Environment.UserName`，与 CLI 语义一致。
- **校验**：规则 ID / 路径 glob / 指纹至少填一项；原因 trim 后 5–256 字符；规则 ID 需匹配 `^(GGD|USR|GLK)/[A-Z]+/[A-Z0-9_-]+$`；指纹为 64 位十六进制 SHA-256。校验通过后调用后端，`AllowlistException` 的 `ALLOWLIST_VALIDATION_FAILED` / `ALLOWLIST_NOT_FOUND` 映射为本地化消息。
- **状态**：`IsLoadingPage` / `IsBusy`、`CurrentPage` / `TotalPages` / `TotalCount`、`HasPendingDelete`、`IsEmpty`；页面请求以递增版本号丢弃过期响应，新增成功后回到第 1 页，删除当前页最后一条时自动回退一页。
- **本地化**：`Relocalize` 刷新页面标签、分页文案、条目元信息与操作按钮；缓存的仓库页在全局语言切换时同样刷新。

### 3.7 `RulesView`（GGD-0045）

- **数据源**：`RulesViewModel`（构造注入 `IRuleOperations` 与初始语言，搜索节流窗口可注入用于测试），由 `MainViewModel` 在首次进入「规则」导航时创建并在会话内缓存。
- **布局**：顶部标题 / 刷新按钮 / 加载条与筛选工具栏（搜索框、来源 / 类别 ComboBox、仅启用 CheckBox、摘要与错误消息），左侧规则列表与 Gitleaks 分类说明 / 空状态，右侧为选中规则详情（规则 ID / 名称 / 类别 / 严重度 / 来源 / 启用状态 / 正则）。
- **服务契约**：`IRuleOperations.LoadCatalogAsync` 以 `Task.Run` 调用 `GitGuardSession.GetRuleCatalog()`，返回 `RuleCatalogSnapshot`（规则条目、`GitleaksEnabled`、`GitleaksPath`），与 `gitguard rules list` 共用目录构建逻辑。
- **筛选**：搜索按规则 ID / 名称大小写不敏感，默认 200ms 节流（`CancellationTokenSource` + 递增版本号丢弃过期输入）；来源（全部 / 内置 / 自定义 / Gitleaks）、类别（全部 / Secret / Privacy / LocalPath / Url）与「仅启用」可组合；筛选后原选中项仍可见则保留，否则选中首条。
- **正则边界**：`RuleItemViewModel` 不持有正则原文；`RulesViewModel` 私下保存模式文本，默认返回本地化隐藏占位，切换选中规则自动重置隐藏状态，仅显式切换后展示原文。
- **Gitleaks 分类**：静态目录不含 Gitleaks 条目，筛选到该来源时展示适配器启用状态 / 可执行文件路径或 `rules.secrets.use_gitleaks = false` 提示，并以 Gitleaks 专属空状态说明动态规则。
- **本地化**：`Relocalize` 刷新页面标签、筛选选项、摘要、规则元信息与 Gitleaks 说明；缓存的规则页在全局语言切换时同样刷新。

### 3.8 `LogsView`（GGD-0046）

- **数据源**：`LogsViewModel`（构造注入 `IAuditOperations`、`IExportPathPicker?`、初始语言与可注入时钟），由 `MainViewModel` 在首次进入「日志」导航时创建并在会话内缓存。
- **布局**：顶部标题 / 刷新按钮 / 加载条与导出按钮，筛选卡（结果 ComboBox、时间范围 ComboBox、摘要与导出提示），审计记录列表（时间 / 仓库 / 结果 / 详情四列，行内展示仓库名与路径、结果、扫描类型 / 发现数 / 耗时 / 退出码摘要），空状态与错误消息，底部上一页 / 页码 / 下一页。
- **服务契约**：`IAuditOperations.QueryAsync(AuditQuery)` 以 `Task.Run` 调用 `AuditListUseCase.Execute`；`ExportAsync(outputPath, format)` 调用 `AuditExportUseCase.Execute`，输出与 `gitguard audit export` 完全同契约。`IExportPathPicker.PickSaveFileAsync` 由 `StorageProviderExportPathPicker` 通过 Avalonia `StorageProvider` 实现，非桌面宿主下返回 `null`。
- **分页与筛选**：每页 20 条（`AuditQuery.DEFAULT_LIMIT`）；结果筛选全部 / Clean / Warned / Blocked / Failed，时间范围全部 / 7 / 30 / 180 天，筛选变化回到第 1 页；请求以递增版本号丢弃过期响应，页码越界自动回退。
- **导出边界**：建议文件名 `gitguard-audit-yyyyMMdd-HHmmss.json|csv`；用户取消不写文件也不提示；成功消息包含记录数与输出路径，失败按本地化消息呈现；导出期间 `IsExporting` 禁用导出命令。
- **本地化**：`Relocalize` 刷新页面标签、筛选选项、分页文案、记录行结果 / 扫描类型 / 摘要与导出提示；缓存的日志页在全局语言切换时同样刷新。

### 3.9 `SettingsView`（GGD-0046）

- **数据源**：`SettingsViewModel`（构造注入 `AppState`、`ISettingsOperations` 与初始语言），由 `MainViewModel` 在首次进入「设置」导航时创建并在会话内缓存。
- **布局**：顶部标题 / 加载条；外观卡（语言 ComboBox、主题 ComboBox 与说明）；Gitleaks 卡（覆盖状态、启用 CheckBox、路径 TextBox、提示、保存与恢复按钮、消息条）。
- **服务契约**：`DesktopSettingsService` 以 `desktop-settings.json` 持久化语言 / 主题 / Gitleaks 覆盖（schema 版本 1、原子替换、UTF-8 无 BOM；缺失 / 损坏 / 版本不匹配回退默认值）；`LoadGitleaksAsync` 返回 `config.yml` 合并后的有效 Gitleaks 设置。覆盖通过 `GitGuardConfigOverrides` 在配置合并后应用，不写回 `config.yml`。
- **状态**：`IsLoading` / `IsSaving`、`HasOverride` / `CanResetGitleaks`、`Message` / `IsMessageError`；`EnsureLoadedAsync` 只加载一次；语言与主题选择变更即写 `AppState` 并持久化，Gitleaks 覆盖需显式保存。
- **主题与语言**：`SelectedTheme` 映射 `DesktopThemeMode.System/Light/Dark`，`MainWindow` 绑定 `RequestedThemeVariant` 即时生效；`Relocalize` 刷新选项标签并从 `AppState` 同步语言选择，避免语言切换触发重复保存。
- **本地化**：`Relocalize` 刷新页面标签、语言 / 主题选项、Gitleaks 表单与覆盖状态；缓存的设置页在全局语言切换时同样刷新。

## 4. 状态管理

- **本地状态**：UI 临时态（如展开/折叠）保留在 View（`StyledProperty`）或 ViewModel。
- **跨组件状态**：通过 ViewModel 组合 + 依赖注入；共享状态保持单向数据流（上层 ViewModel 持有，下级通过 Props 读取）。
- **全局状态**：
  - `AppState`（应用级：当前语言、主题、版本）由 `App.axaml.cs` 组合根创建，并在进程内保持单例后注入 `MainViewModel`；`GGD-0042` 同时把 `GitGuardSession` 包装为 `RepositoryOperations` 注入仓库页，当前尚未引入 DI 容器。`GGD-0046` 将全部桌面服务收拢为 `DesktopServices` 聚合注入 `MainViewModel`，`AppState` 的语言与主题变更通过 `DesktopSettingsService` 持久化，重启时回读。
  - 不引入 Redux / 事件总线等重量级框架；MVVM + DI 已足够。
- **服务端/异步状态**：MVP 桌面端的「服务端」即本地 CLI 进程；用 `ScanService.ScanAsync()` 返回 `Task<ScanResult>`。

## 5. 组件通信

- **父子**：Props + Events；禁止子组件直接改父组件状态。
- **跨层级**：通过 ViewModel 组合，不使用全局事件总线（避免难以追踪的隐式耦合）。
- **跨 Window**：使用 `IMessenger`（CommunityToolkit.Mvvm 内置），限定 Message 类型清单，不开放匿名 Payload。

## 6. 性能规范

- 列表虚拟化：`VirtualizingStackPanel`（Avalonia 内置），`ItemsRepeater` 优先于 `ListBox`。
- 大量 findings：按仓库 + 时间分段加载；不一次性拉所有。
- 防抖/节流：
  - 筛选输入框 `TextChanged` 节流 200ms。
  - 规则库搜索节流 200ms。
- 禁止在 UI 线程做 SQLite / 配置加载；`RepositoryOperations` 的十个操作（仓库 / 扫描 / 历史 / 白名单）、`RuleOperations.LoadCatalogAsync` 与 `AuditOperations` 的查询 / 导出均以 `Task.Run` 执行，ViewModel 只 `await` 并更新绑定属性。

## 7. 可测试性

- **ViewModel 单测**：命令触发、属性变更、状态流转全部可单测（无需启动 Avalonia）。`tests/GitGuard.Desktop.Tests` 当前 121 例：`AppState` / `MainViewModel` 的语言与主题切换、导航顺序与页面缓存；`RepositoriesViewModel` 的列表 / 登记 / 扫描 / 移除确认 / 错误映射 / 语言刷新；`ScanHistoryViewModel` 的分页 / 运行与发现项选择 / 脱敏与金丝雀隔离 / 编辑器跳转 / 过期响应；`AllowlistViewModel` 的分页 / 三条件校验 / 指纹校验 / 新增与删除确认 / 错误映射 / 语言刷新；`RulesViewModel` 的目录加载 / 搜索节流 / 来源与类别筛选 / 有效启用 / 正则隐藏 / Gitleaks 说明 / 错误映射 / 语言刷新；`LogsViewModel` 的分页 / 结果与时间范围筛选 / JSON 与 CSV 导出 / 取消与错误处理 / 语言刷新；`SettingsViewModel` 的有效值加载 / 覆盖保存与清除 / 语言与主题持久化 / 错误与重新本地化；`DesktopSettingsService` 的 JSON 往返 / 损坏与版本回退 / 原子写入；`ShellEditorLauncher` 的缺失与路径逃逸校验；`RepositoryItemViewModel` 与 `HookStatusRowViewModel` 的徽标和 Hook 状态文案。
- **View 快照测试**：使用 Avalonia 的 `HeadlessApplication` + 像素级 Snapshot（仅针对关键页面）。`Avalonia.Headless.XUnit` 11.3 依赖 `xunit.core` 2.4，与仓库的 `xunit.v3` 冲突，暂不引入；`GGD-0041` 以真实启动 + 截图人工核验导航与中英切换，待官方提供 xunit.v3 兼容包后补自动化快照。
- **E2E**：首期不做自动 E2E；用手动验收清单覆盖主流程（见 `16-测试方案.md` §9）。

## 8. 设计系统集成

- **Theme**：`FluentTheme` + 自定义品牌色 Token；`App.axaml` 的 `ThemeDictionaries` 定义 Light / Dark 两套侧边栏、选中态、悬停态、内容面板、边框与文字画刷。
- **Icon**：Fluent System Icons（通过 `Projektanker.Icons.Avalonia` 加载）。
- **深色模式**：`GGD-0046` 由 `MainWindow` 绑定 `MainViewModel.RequestedThemeVariant`；`AppState.ThemeMode` 默认 `System`（`ThemeVariant.Default`），可强制 `Light` / `Dark` 并持久化到桌面设置文件。
