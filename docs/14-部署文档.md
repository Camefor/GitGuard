# 发行与分发（原部署文档）

> **范围说明**：GitGuard 是**本地单机工具**，不涉及传统意义的「服务器部署」。本文件改写为「发行与分发」：如何打包、如何让开发者安装、如何升级、如何回滚。

## 1. 分发矩阵

| 分发形态 | 目标用户 | 平台 | 产出 |
| --- | --- | --- | --- |
| Native AOT 单文件 | 偏好「下载即用」的开发者 | Windows x64 / Linux x64 / macOS x64, arm64 | `gitguard-<version>-<rid>.zip`（内含可执行文件 + 校验和） |
| `dotnet tool` 全局工具 | 已有 .NET SDK 的开发者 | 所有 .NET 10 支持的平台 | NuGet 包 `GitGuard.Cli` |
| 包管理器（P2 规划） | 跟随平台惯例 | Homebrew / Scoop / winget / apt 第三方源 | Formula / Manifest |
| 桌面端安装包 | 偏好图形化安装的用户 | Windows x64 MSIX / macOS arm64 + x64 DMG / Linux x64 AppImage | `gitguard-<version>-<rid>.msix` / `.dmg` / `.AppImage`，另见 §9 |

## 2. 配置管理

- GitGuard 的「配置」仅指：
  - 用户级 `~/.config/gitguard/config.yml`
  - 项目级 `<repo>/.gitguard.yml`
  - 环境变量：`NO_COLOR`（已实现）；`GITGUARD_SKIP=1`（已实现，仅在 Hook 模式生效，`GGD-0013`）、`GITGUARD_LANG`（已实现，`GGD-0014`，命令行 `--language` 优先）
- 不涉及传统意义的「密钥配置」；工具内部需要的 `fingerprint_salt` 由首次运行自动生成（见 `08-权限设计.md` §4）。
- 配置优先级：**命令行参数 > 环境变量 > 项目级 YAML > 用户级 YAML > 内置默认**。

## 3. 发行流程

```mermaid
flowchart LR
    PR[PR 合入 main] --> CI[CI 构建 & 测试]
    CI --> Tag[打版本 Tag v1.1.0]
    Tag --> Pack[Native AOT 多平台构建]
    Pack --> Publish[发布到分发渠道]
    Publish --> Smoke[用户侧冒烟]
    Smoke --> Done[发布完成]
```

- **CI 流水线**（`.github/workflows/ci.yml`）：PR / push（`main` / `master`）触发 `windows-latest` 单平台流水线，依次执行 restore → build（Release，警告即错误）→ 单元（Core / Detection）→ 集成（Infrastructure / Application）→ 契约（Cli）→ 场景（E2E）；`hook-compat` 作业在 Windows 上运行。另设 `desktop-package-smoke` 作业：构建 Windows MSIX，解包后用 CLI 在隔离数据目录写入真实审计记录，再以 `--smoke-test` 启动桌面端验证读取与导出（`GGD-0047`）。macOS / Ubuntu 测试矩阵与 Linux DR-01 `strace` 安全作业不再计划（`GGD-0028` 已取消）。
- **发行构建**（`.github/workflows/release.yml`）：推送 `v*` Tag 或手动触发，先统一解析版本号（Tag 去掉 `v` 前缀，手动触发可覆盖），再执行两组作业：
  - **CLI AOT**：按 RID 矩阵 `win-x64` / `linux-x64` / `osx-arm64` / `osx-x64`（macOS x64 在 arm64 runner 上交叉编译，不执行本机冒烟）运行 Native AOT 发布；原生平台在打包前执行 `gitguard version` 冒烟。
  - **桌面安装包**：`desktop-windows`（MSIX）、`desktop-macos`（arm64 原生 + x64 交叉 DMG）、`desktop-linux`（AppImage）。每个作业下载对应 RID 的 CLI 产物作为冒烟夹具，安装包构建成功后用 `build/desktop/smoke-test.ps1` 验证「CLI 写入审计 → 桌面端读取明细并导出」。
- **产物形态**：每个 RID 输出 `gitguard-<version>-<rid>.zip`（内含平台可执行文件、Windows 的 `e_sqlite3.dll` 与 `SHA256SUMS`）；桌面端输出 `gitguard-<version>-<rid>.msix` / `.dmg` / `.AppImage`，作为独立 Actions 构件 `gitguard-desktop-<version>-<rid>` 上传，保留 30 天。Linux / macOS 由 `zip` 打包以保留可执行位（GitHub Actions artifact 服务本身不保留文件权限）。
- **签名与公证**：
  - Windows：MSIX 支持通过 `GITGUARD_MSIX_CERT_BASE64` / `GITGUARD_MSIX_CERT_PASSWORD` 注入 PFX 并调用 `signtool` 签名；未配置时产出未签名 MSIX，仅用于解包冒烟 / 本地开发者模式安装。CLI 的 Authenticode 签名仍为 P2 规划。
  - macOS：默认 ad-hoc 签名；配置 `GITGUARD_MACOS_SIGNING_IDENTITY` 后改用 Developer ID 签名，再配置 `GITGUARD_MACOS_NOTARY_APPLE_ID` / `GITGUARD_MACOS_NOTARY_TEAM_ID` / `GITGUARD_MACOS_NOTARY_PASSWORD` 时提交 notarization 并 stapling。
  - Linux：AppImage 未签名；GPG 签名发行物仍为 P2 规划。
- **校验和**：每个发行物附带 `SHA256SUMS` 与可选 GPG 签名。
- **渠道发布**（P2 规划）：MVP 阶段产物由 Actions 运行页下载；GitHub Release / 包管理器渠道发布随签名一并落地。
- **v1.0 发布基线**（`GGD-0053`）：版本号冻结为 `1.0.0`，发行说明见 [`20-v1.0发行说明.md`](./20-v1.0发行说明.md)。Windows CLI AOT / 发行 zip / MSIX 已在本地完成发行冒烟；正式公开发布前仍需 macOS / Linux 在首次 Release runner 上完成原生冒烟。

## 4. 升级

- CLI 内置 `gitguard version` 显示当前版本；暂不内置自动更新。
- `dotnet tool` 用户：`dotnet tool update -g GitGuard.Cli`。
- 包管理器用户：按平台惯例（`brew upgrade gitguard` / `scoop update gitguard`）。
- **规则库更新**：MVP 规则库随发行物内置；二期可通过 `gitguard rules update`（可选，默认不走网络；用户显式开启后从仓库 Releases 拉）。

## 5. 回滚

- CLI 回滚 = 用户卸载当前版本并安装旧版。
- 用户仓库的 Hook 经 `gitguard install` 幂等重跑刷新（已托管脚本按版本刷新；未托管的文本 Hook 自动备份包裹）；`--force` 仅用于接管二进制 / 符号链接形态的目标。
- 回滚不会损坏 SQLite 审计数据库；向后兼容规则：**任何 schema 迁移必须向后兼容最近一个 MINOR 版本**。

## 6. 灰度与特性开关

- MVP 不内置 Feature Flag 框架；新规则通过「新增并默认 `enabled: false`」做软上线。
- 用户可在 `.gitguard.yml` 中启用预览规则：

  ```yaml
  rules:
    "GGD/PRIVACY/BANKCARD":
      enabled: true  # 预览期默认关闭
  ```

## 7. 环境隔离与数据保护

- 不同操作系统用户的 audit.db 自然隔离（权限 `0600`，位置在各自用户目录）。
- 工具不会读写 `~/.ssh/`、`~/.aws/` 等常见凭据目录；原 Linux CI 的 `strace` 检查随跨平台矩阵取消（`GGD-0028`）。
- CI 环境禁止把真实 production 规则包埋入镜像；CI 使用「合成规则包」。

## 8. 发布节奏与窗口

- MVP 阶段按「里程碑驱动」而非固定周期；详见 `17-开发RoadMap.md`。
- 进入维护期后目标：每 2 周一个 PATCH；每 2 月一个 MINOR。

## 9. 桌面端安装包

桌面端与 CLI 分离发行，安装包只包含自包含的 `GitGuard.Desktop`（不依赖目标机 .NET 运行时），与 CLI 共用同一用户数据目录中的 `audit.db`。Windows / macOS / Linux 分别由 `build/desktop/package-*.ps1` 构建，入口均为 PowerShell 7（Windows 打包脚本使用 Windows SDK 的 `MakeAppx`，仅 Windows 可运行）。

### 9.1 Windows MSIX

```powershell
./build/desktop/package-msix.ps1 -Version 0.3.0 -OutputDirectory artifacts/desktop
```

- 发布 `win-x64` 自包含桌面端，将 `build/desktop/assets/*.png` 写入 `Assets/`，生成 `gitguard-<version>-win-x64.msix`。
- 未配置证书时产出**未签名 MSIX**：可被 `unpack-msix.ps1` 解包冒烟，但安装到系统需开启开发者模式或信任自签证书。
- 配置 `GITGUARD_MSIX_CERT_BASE64`（PFX 的 Base64）与 `GITGUARD_MSIX_CERT_PASSWORD` 后自动用证书 Subject 作为 Publisher 并调用 `signtool` 签名。
- 通过开始菜单启动；自动更新（`App Installer` 协议）未实现，升级需重新安装新版 MSIX。

### 9.2 macOS DMG

```bash
pwsh ./build/desktop/package-dmg.ps1 -Version 0.3.0 -Runtime osx-arm64 -OutputDirectory artifacts/desktop
```

- 发布自包含 `.app`（`Contents/MacOS` + `Info.plist` + `GitGuard.icns`），用 `hdiutil` 生成可拖拽安装的 `gitguard-<version>-<rid>.dmg`。
- `-Runtime` 支持 `osx-arm64` / `osx-x64`；`osx-x64` 可在 arm64 runner 上交叉发布，但不执行本机冒烟。
- 默认 ad-hoc 签名；正式分发需配置 Developer ID 与 notarization 凭据（见 §3）。未公证产物首次启动需在「系统设置 → 隐私与安全性」中手动放行。
- Homebrew Cask 渠道为后续规划。

### 9.3 Linux AppImage

```bash
pwsh ./build/desktop/package-appimage.ps1 -Version 0.3.0 -OutputDirectory artifacts/desktop
```

- 发布 `linux-x64` 自包含桌面端，组装 `AppDir`（`AppRun` / `.desktop` / 图标）后调用 `appimagetool` 生成 `gitguard-<version>-linux-x64.AppImage`，无需 root 安装。
- `appimagetool` 从 AppImageKit release 13 下载并缓存在 `build/desktop/.tools`；CI 中设置 `APPIMAGE_EXTRACT_AND_RUN=1` 以免依赖 FUSE。
- Flatpak 渠道为后续规划。

### 9.4 发行冒烟

`build/desktop/smoke-test.ps1` 在隔离的数据 / 配置目录中执行端到端检查，Windows PowerShell 5.1 与 PowerShell 7 均可运行：

1. 创建临时 Git 仓库并暂存金丝雀 Token（`AKIAIOSFODNN7EXAMPLE`），用发行版 CLI 执行 `scan --staged`，要求退出码 1 并写入审计记录；
2. 启动桌面端 `--smoke-test --data-directory <隔离目录> --expected-runs 1 --report <json> --export <json>`，该模式在 Avalonia 初始化前执行，不需要显示环境；
3. 断言桌面端能查询到审计运行、读取最近运行明细（Finding 数 > 0、结果 `Blocked`），并通过 `IAuditOperations` 导出与查询总数一致的全部记录。

报告 schema 为 `gitguard.desktop.smoke.v1`，字段包含 `ok` / `auditRunCount` / `latestRunFindingCount` / `exportedRunCount` / `error` 等。CI 的 `desktop-package-smoke` 作业与 Release 的三平台桌面作业都复用该脚本；失败时保留工作目录并输出 CLI 日志路径便于定位。

## 10. 发行后冒烟清单

每次发布 Tag 后在三平台各运行一次。

### 10.1 CLI

- [ ] `gitguard version` 显示正确版本。
- [ ] 新建 Git 仓库 → `gitguard install` 成功。
- [ ] 构造「金丝雀 Token」提交 → `pre-commit` 阻断。
- [ ] `git commit --no-verify` → `post-commit` 登记 `BypassDetected`（`Reason = NoVerify`）；`GITGUARD_SKIP=1 git commit` → `Reason = GitGuardSkip`。
- [ ] `gitguard scan --staged` 完整扫描一个 10 文件项目；`gitguard scan --all` 复核 HEAD 全量快照。
- [ ] `gitguard uninstall` 恢复原状。
- [ ] `gitguard audit list` 能列出本次冒烟产生的扫描记录；`gitguard audit export --output smoke.json --format json` 导出的文件不含原文。仍可直接查询 `audit.db` 复核。

### 10.2 桌面端安装包

每个平台先执行 `build/desktop/smoke-test.ps1`（CI / Release 已自动执行），再人工确认 UI：

- [ ] 安装包能启动并显示主窗口（Windows MSIX 解包目录或已安装开始菜单项、macOS DMG 拖拽后的 `.app`、Linux AppImage）。
- [ ] 在隔离数据目录中用 CLI 写入审计记录后，桌面端「日志」页显示的运行数量与 `gitguard audit list` 一致。
- [ ] 选中最新运行后能查看脱敏 Finding 明细，界面不出现金丝雀 Token 原文。
- [ ] 通过「日志」页导出 JSON / CSV，导出记录数与 CLI 查询总数一致。
- [ ] 安装包内 `--smoke-test` 报告 `ok = true`，且 `latestRunResult = Blocked`、`latestRunFindingCount >= 1`。
