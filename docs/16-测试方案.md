# 测试方案

## 1. 测试策略

GitGuard 作为**安全工具**，测试策略以「真实场景覆盖」优先于「覆盖率数字」：

1. **测试驱动不变式**：DR-01 ~ DR-06 的每一条都必须有独立测试用例（即使正常 FR 测试已覆盖）。
2. **FailClosed 用故障注入验证**：模拟 Git 命令失败、Regex 超时、SQLite 锁定，确认退出码 ≥ 10。
3. **测试左移**：核心规则正则在合入前跑 ReDoS 用例集；配置文件 Schema 校验跑在单测里。
4. **真实 Git 集成**：E2E 测试通过 `Fixture` 启动 `git init` 临时仓库，调用真实 `git`、`gitguard` 二进制，验证 Hook 行为。
5. **金丝雀 Token 自检**：所有本地审计 / 日志路径不得包含 `AKIA_SENTINEL_${run_id}` 原文——CI 全路径跑一次。

## 3. 测试用例命名与追溯

- 单元/集成测试类：`<ClassUnderTest>Tests`。
- 测试方法：`<Method>_<Scenario>_<Expectation>` 或 `When_<State>_Should_<Behavior>`。
- 契约 / 场景 / DR 用例：显式用「TC-\*」命名注释（供文档追溯），例如：

  ```csharp
  // TC-DR-04-01
  [Fact]
  public async Task PreCommitScan_ShouldNotReadWorkingTreeFiles()
  { ... }
  ```

- 每个 FR / NFR / DR 必须至少有一条 TC 追溯；追溯矩阵在 `02-SRS §8`。

## 6. 外部依赖测试

- **Git CLI**：E2E 直接调用真实 `git` 二进制；CI 在 `ubuntu-24.04` / `windows-latest` / `macos-14` 上使用 runner 自带的最新稳定 Git（NFR-A-002）。原「Git 2.9 / 2.40 / 最新三档」矩阵因托管 runner 无法提供旧版本（且 E2E 夹具的 `--initial-branch` 要求 Git ≥ 2.28）顺延至 `GGD-0017`。
- **Gitleaks**（P2）：集成测试提供 Mock Adapter 与真实二进制两种模式；真实二进制在 PR 测试中可选跳过（CI 用 cache 提速）。
- **SQLite**：使用临时文件，不依赖 in-memory 模式，确保与生产行为一致。

## 7. 性能测试

| 基准 | 工具 | 阈值 |
| --- | --- | --- |
| 冷启动 | 自写脚本 50 次 | P95 ≤ 150ms（Native AOT 发行物）|
| 暂存区扫描 | BenchmarkDotNet，500 行差异 | P95 ≤ 500ms |
| 推送扫描 | BenchmarkDotNet，50 提交 × 100 行 | P95 ≤ 2000ms |
| 全量扫描吞吐 | 100 MB 项目 | ≥ 20 MB/s |

超阈值 → 分析规则级耗时（`--trace` 日志），优化或禁用高耗规则。

## 8. 安全测试

- **ReDoS 用例集**：对所有规则正则跑 10 条已知灾难性回溯模式；超时即判定测试失败。
- **路径穿越**：构造 `../../etc/passwd` 等文件路径，确认 Hook 分发器脚本不会被攻击者构造的仓库名注入。
- **ANSI 注入**：恶意文件路径含控制字符时，终端输出被 `TerminalSanitizer` 过滤。
- **CI 组合扫描**：`trivy` 对依赖包做 CVE 扫描；仅提醒不阻断。

## 10. 测试数据策略

- **规则正则样本**：维护在 `tests/GitGuard.Detection.Tests/Fixtures/*.txt`，按规则 ID 组织「positive / negative / edge」三类。
- **金丝雀 Token**：每次测试运行时按 `AKIA_SENTINEL_<runId>` 生成唯一值；避免跨 case 污染。
- **真实敏感数据**：**严禁**入库入日志；任何需要演示的密钥都用 `example`、`sentinel`、`demo` 前缀。

## 11. 持续集成

- **流水线阶段**：`.github/workflows/ci.yml` 实现 `restore → build → unit（Core / Detection）→ integration（Infrastructure / Application）→ contract（Cli）→ scenario（E2E）→ security（Linux DR-01）`；`.github/workflows/release.yml` 在 `v*` Tag 或手动触发时执行 `publish-artifacts`（`win-x64` / `linux-x64` / `osx-arm64` / `osx-x64` Native AOT）。
- **三平台矩阵**：`ubuntu-24.04` / `windows-latest` / `macos-14`，`fail-fast: false`——单平台失败不掩盖其余平台结果。
- **失败阻断策略**：
  - 单元 / 集成 / 场景 / 安全测试任一失败 → 阻断合入。
  - 性能测试仅在 MINOR 发布节点阻断；日常 PR 失败只警告。
- **测试报告归档**：当前保留 Actions 运行日志；trx + coverage 归档随 `GGD-0018` 补齐。
- **Analyzer 结果**：StyleCop + Roslynator 发现的任何 Error 级问题阻断（Release 构建 `TreatWarningsAsErrors`）。
- **格式门禁**：`dotnet format --verify-no-changes` 实测存在 86 处既有 IDE1006 命名规则冲突（src 与 tests 均有），暂未纳入 CI，顺延至 `GGD-0018`。
