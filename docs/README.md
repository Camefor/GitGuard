# GitGuard 项目文档

## 1. 文档定位

本目录是 **GitGuard** 的需求与设计基线。GitGuard 是面向开发者的本地 Git 敏感信息防泄漏工具，在 `git commit` / `git push` 前通过 Hook 拦截 Token、密钥、密码、手机号、本地路径、内网 URL 等敏感信息。实现、测试、部署发生变化时，必须同步更新对应文档。

> AI 执行仓库任务前必须先阅读 [Agent 工作指南与任务台账](./AGENT-GUIDE.md)。该文档记录启动流程、按任务选读的设计文档、待办/已办状态、任务恢复点和会话收尾要求。

- 产品版本：`1.1.0`（`GGD-0054` / `GGD-0055`：桌面端 Hook 快捷安装 / 卸载与共享 Hook 管理服务；1.0.0 发布基线的 macOS / Linux 发行冒烟与 3 个月稳定运行观察仍待完成）
- **MVP (P1)**：已完成——CLI + Git Hook 分发器 + 四类检测器（Secret / Privacy / LocalPath / Url）+ SQLite 审计 + `.gitguard.yml` 配置
- **第二阶段 (P2)**：开发完成——规则分级、项目白名单、仓库全历史扫描、Gitleaks 适配器集成、误报治理指南；真实项目试用验收待用户执行

## 4. 核心设计约束

1. **本地化**：所有扫描、规则匹配、审计写入必须在本机完成；不得向任何外部服务发送代码或敏感衍生物。详见 CONTEXT §5 DR-01。
2. **零明文留存**：审计数据库、日志、临时文件均禁止写入 Token / 密码 / 完整敏感行原文；只记录脱敏指纹。详见 CONTEXT §5 DR-02 与 `09-日志设计.md` §9。
3. **FailClosed**：扫描器异常时默认拒绝 `commit` / `push`；禁止「静默放行」。详见 ADR-0003 与 `10-异常处理设计.md` §5。
4. **暂存区真实**：`pre-commit` 必须通过 `git diff --cached` 读取，不得使用磁盘整文件。详见 CONTEXT §5 DR-04。
5. **Hook 兼容**：安装不得静默覆盖已有 Hook（Husky / lefthook / pre-commit），必须通过 `HookDispatcher` 链式调用。详见 [ADR-0004](./adr/0004-Hook分发器方案.md) 与 `模块设计/Hook.md`。
